## 1. 验收目标

本次验收的目标，不是证明 NeoDev 已经“全部完成”，而是确认 **Week1 约定范围内的核心链路已经形成最小可用闭环**，具体包括：

1. 项目级需求路由已经可用。
2. 仓库噪音已被基本收敛，后续提交可读性提升。
3. 产品版本与项目分支之间的映射逻辑已从“前端兜底”下沉到后端。
4. 提交列表已经支持按 `project + branch` 查询，并支持分页。
5. 项目同步时，若缺失项目级 version，后端会自动补建，减少空结果和链路断裂。
6. 前端分支视图已经接入新的后端能力，形成可验证的前后端闭环。
7. 当前成果至少通过了核心后端测试、前端测试与前端构建验证。

## 5. 具体验收步骤

以下步骤按“最值得先验”的顺序编排。老大不一定要全做，但建议至少完成前 3 组。

## 验收项 1：项目级需求路由可用

### 验收目标
确认项目级需求接口已正式暴露，不再出现主路由未挂载的问题。

### 操作步骤

1. 启动后端服务。
2. 使用已有测试数据或新建一个项目。
3. 调用项目级需求列表接口：
   - `GET /api/projects/{project_id}/requirements`
4. 继续执行新增、编辑、删除或 commit 绑定相关动作。

### 预期现象

- 接口返回 200。
- 空数据时返回空列表，而不是 404 或路由不存在。
- 新增/修改/删除/绑定提交等动作可访问并返回合理结果。

### 通过标准

满足以下条件即可判定通过：

- 路由可访问；
- 基本 CRUD 不报“接口不存在”；
- 与需求相关的接口契约与测试表现一致。

---

## 验收项 2：分支映射时自动补建项目级 version

### 验收目标
确认设置产品版本分支映射后，后端会自动补齐项目级 version，不需要前端临时补锅。

### 操作步骤

1. 选择一个产品、一个项目、一个目标分支（例如 `main` 或 `develop`）。
2. 确保该项目当前不存在对应 `project + branch` 的项目级 version。
3. 在产品版本中设置该项目分支映射。
4. 再次查询该项目 versions。

### 预期现象

- 设置映射成功。
- 系统自动生成对应的项目级 version。
- 重复设置同一映射时，不应产生重复脏数据。

### 通过标准

满足以下条件即可判定通过：

- 首次设置后能查到自动创建的 version；
- 重复执行不会无限新增重复记录；
- 前端无需额外做兜底创建才能继续链路。

---

## 验收项 3：按分支查看提交列表 + 分页可用

### 验收目标
确认前后端已经围绕 `project + branch` 形成提交查询闭环，且提交列表支持分页。

### 操作步骤

1. 进入某产品下的项目详情页。
2. 选择已建立分支映射的分支。
3. 查看提交列表。
4. 继续点击下一页/继续加载（若前端为分页或加载更多）。
5. 观察是否仍通过 `project + branch` 拉取数据，而不是依赖手工 version ID。

### 预期现象

- 首屏可以加载该分支的提交。
- 有数据时能显示提交记录；无数据时给出空态而不是异常。
- 分页继续加载时结果自然衔接。
- 不需要先手工查 `version_id` 才能完成查询。

### 通过标准

满足以下条件即可判定通过：

- 首屏可加载；
- 分页可继续；
- 页面不因缺少 `version_id` 而中断；
- 接口与页面行为一致。

---

## 验收项 4：项目同步时自动补建 version

### 验收目标
确认同步链路不会因项目级 version 缺失而直接失效。

### 操作步骤

1. 选择一个已存在产品分支映射、但项目级 version 缺失的项目/分支组合。
2. 执行项目同步提交操作。
3. 同步完成后查看该项目 versions 与提交列表。

### 预期现象

- 同步过程中若发现缺少项目级 version，系统自动补建。
- 同步结果不再因为 version 缺失而直接为空。
- 补建后能继续查询到同步后的提交结果。

### 通过标准

满足以下条件即可判定通过：

- 同步链路不断；
- 自动补建真实发生；
- 同步后可看到对应提交数据或合理空态。

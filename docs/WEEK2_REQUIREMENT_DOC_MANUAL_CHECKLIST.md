# Week2 Requirement Doc Manual Checklist

适用对象：非开发验收人员  
目标：按固定步骤复现 Week2 requirement doc 主链，并判断主链是否可持续 review、可重复验收。  
范围：只覆盖“进入需求文档页 → 读取状态 → 生成/续生成 → diff/review/save → 树状态回显 → 子文档门禁/生成”的主链。

## 1. 验收前准备

1. 打开 NeoDev，并确认产品、版本、需求树已经存在。
2. 在需求树中准备至少这些节点：
   - 1 个 Epic
   - 1 个 Story
   - Story 下至少 1 个 Task，或允许系统后续拆分创建
3. 确认当前环境可访问 requirement doc 页面，且 AI 生成功能可用。
4. 记录本次验收时间、产品名、版本名、验收人。

## 2. 主链验收步骤

### A. 读取文档与空态/失败态区分

1. 进入一个从未生成过文档的 Story 或 Epic 的需求文档页。
2. 预期：
   - 页面显示“当前还没有需求文档”或同义空态提示。
   - 页面仍可编辑，且可看到“AI 生成文档”入口。
   - 这不是报错页。
3. 刷新页面。
4. 预期：
   - 仍然是空态，不应变成加载失败。
5. 如环境支持模拟异常，断开后端或制造读取失败后重进页面。
6. 预期：
   - 页面显示“文档加载失败”或同义错误态。
   - 页面应提供“重试加载”按钮。
   - 不应把失败态误显示为空白编辑器。

### B. 生成状态展示

1. 在空态页点击“AI 生成文档”。
2. 预期：
   - 状态卡切到“文档生成中”。
   - 页面可见生成中提示，最好能看到步骤/进度。
3. 在生成过程中刷新页面。
4. 预期：
   - 页面能恢复“后台仍在生成”的状态，不会丢失语义。
5. 若本次生成失败，预期：
   - 页面显示“文档生成失败”或同义提示。
   - 失败原因可见。
   - 用户可以重试或续生成。

### C. 保存、版本刷新与 diff 最短路径

1. 文档生成完成后，确认页面出现正文内容。
2. 修改文档中的一小段文字。
3. 点击“保存”。
4. 预期：
   - 页面出现“保存完成”反馈。
   - 当前版本号增加，例如从 v2 变为 v3。
   - 版本列表刷新，可看到最新版本。
5. 进入 diff。
6. 若版本数不足 2 个，预期：
   - 页面显示“还没有可展示的版本差异”或同义空态。
   - 不应报错。
7. 若已有至少 2 个版本，预期：
   - 可以直接查看“当前稿 vs 上一版本”的最短路径 diff。
   - diff 内容与刚才修改一致。

### D. review 闭环

1. 在 diff 页面进入 review。
2. 逐段接受或拒绝改动。
3. 预期：
   - review 结果会回到当前稿。
   - 接受后可继续保存为新版本。
   - 拒绝后应恢复原稿，不残留未解释状态。

### E. 需求树状态回显

1. 返回左侧需求树或重新进入 requirement doc 页面。
2. 预期：
   - 当前节点的文档状态已回显为“已有文档”或等价状态。
   - 若刚完成生成/保存，树上的状态应与页面状态一致。
3. 在存在待审阅改动时，尝试切换到其他需求。
4. 预期：
   - 页面应提示你是否放弃未保存/待审阅改动。

### F. 子文档门禁与允许条件

1. 选择一个还没有父文档的 Epic 或 Story。
2. 预期：
   - “生成子文档”按钮不可用，或点击后展示明确门禁原因。
   - 原因需能让非开发人员理解，例如“请先完成当前需求文档”。
3. 完成该父节点文档的生成并保存。
4. 重新查看门禁。
5. 预期：
   - 门禁解除，可以生成子文档。
6. 若父文档仍在生成中或已失败，预期：
   - 子文档入口继续被拦截，并显示对应原因。

### G. 子文档生成反馈

1. 在已满足门禁的 Epic 或 Story 上触发“生成子文档”。
2. 预期：
   - 页面或侧边树显示子文档级别的进度反馈。
   - 至少能看到“开始生成 / 完成 / 失败”中的关键信号。
3. 流程完成后，预期：
   - 当前页面自动刷新或状态更新。
   - 新创建或已完成的子节点在需求树中可见。
   - 对应子节点后续可继续进入 requirement doc 主链。

## 3. 通过标准

满足以下条件即可判定 Week2 主链通过：

1. 空态、失败态、生成中、生成失败、已有文档这几类状态能被清楚区分。
2. 保存后版本号增加，版本列表刷新，diff 可走通。
3. review 可闭环，不会留下不可解释的中间态。
4. 需求树中的文档状态与详情页一致。
5. 子文档门禁既能拦截，也能在父文档就绪后放行。
6. 子文档生成过程有反馈，结束后结果能回到页面和需求树。

# PRD 质量清单

## 0. NeoDev 受控文档格式

- 每个产物 `.md` 文件都必须从 YAML front matter 开始，不能从 `#` 标题开始。
- 必填字段齐全：`doc_id`、`title`、`aliases`、`tags`、`created`、`updated`、`related`、`doc_type`、`product_key`、`status`、`relations.target`。
- `doc_type` 合法：总 PRD、功能子 PRD 和 README 默认是 `prd`；事实源索引和待确认问题默认是 `tech-design`。
- `relations.target` 只包含真实存在的 `doc_id`，不得保留模板占位符。
- `related` 必须是 Obsidian wikilink，并与正文 `## 关联文档` 小节一致。
- 已运行并通过：
  - `python plugins/neodev-rd-knowledge/sync_obsidian_links.py docs`
  - `python plugins/neodev-rd-knowledge/validate_mvp_docs.py docs`
  - `python plugins/neodev-rd-knowledge/validate_obsidian_docs.py docs`

## 1. 路径与边界

- 输出目录位于命中的子项目内；跨项目输出必须说明原因。
- 产物只包含 README、事实源索引、总 PRD、功能子 PRD 和待确认问题。
- 未把实现代码、API JSON、数据库表设计或部署验证混入本 skill 的产物。
- 主智能体已记录或说明本次编排方式；未把单一智能体自评当作独立评估。

## 2. 主从闭环

- 主智能体负责项目定位、DAG 拆分、分派、合并、冲突裁决和最终收口。
- 事实收集、总 PRD、子 PRD、问题清单等执行职责有明确边界。
- 执行器没有替主智能体扩大范围、改写验收标准或自行收口。
- 评估器独立于执行器，只读检查产物并给出明确结论。
- 评估器允许只读读取命中子项目或仓库相关代码，用于核对 PRD 中引用的代码事实。
- 评估不通过或有风险时，已进入修复循环或明确记录未修复原因。

## 3. 事实源与可追踪

- `00-source-index.md` 覆盖用户输入、本地文档、原型、代码、接口、数据和测试材料中实际使用的来源。
- 每条需求、功能、业务规则、AC、测试场景都填写了来源编号或问题编号。
- 最低链路成立：事实源/问题 -> 需求/功能 -> 业务规则 -> AC -> 测试场景。
- 代码事实没有被直接写成产品目标，除非用户明确确认。
- PRD 中引用的代码事实、接口线索、数据结构线索和现有行为描述，均能在代码仓库中被评估器只读复核。

## 3.1 场景细节

- 总 PRD 包含跨功能典型业务场景，复杂流程必须用场景说明触发条件、操作顺序、数据读写、输出证据、下一步和验收关注点。
- 每个功能子 PRD 都包含“典型场景与细节表”，不能只写用户故事、抽象能力或阶段名称。
- 每个典型场景至少包含：触发条件或用户说法、推荐操作顺序、输入数据、读取事实、写入/变更事实、输出示例关注点、失败反馈、下一步动作、验收关注点。
- 当 PRD 使用“闭环”“流程”“同步”“路由”“提交”“检查”等词时，必须能在场景表中找到对应的具体业务例子。
- 不得用抽象编号、空泛流程图或“完成闭环”一句话替代具体场景细节。

## 4. 总分一致性

- 总 PRD 是业务对象、属性、术语和跨功能规则的唯一来源。
- 子 PRD 只引用总 PRD 的业务口径，不重新定义对象、属性、术语或跨功能规则。
- 子 PRD 发现冲突时，已回到总 PRD 修订，而不是在子 PRD 内另起口径。

## 5. 待确认问题

- 阻塞问题包含当前已知事实、需要确认的选项或开放点、影响章节和阻塞原因。
- 非阻塞问题仅写为候选口径，不写成已确认需求。
- 未确认的 API、表结构、枚举、权限、状态机和业务规则均标为待确认。

## 6. 图表

- 数据流图和时序图只包含事实可支撑的节点、参与方和动作。
- 未确认节点或动作已标注“待确认”并关联 `Q-xxx`。
- 不存在通用 UI/API/DB 链路冒充已确认实现。

## 7. 可测试与可实现

- 每个功能至少包含一个 P0 正向测试场景。
- 每个关键业务规则至少关联一个 AC。
- 每个功能覆盖关键异常场景、失败反馈和回归关注点。
- 子 PRD 明确输入、输出、状态变化、数据读写边界和失败反馈。
- 每个场景都能转化为测试步骤：给定前置条件、执行动作、预期数据变化、预期输出和失败反馈。

## 8. 清理与完整性

- 模板占位符 `<...>`、`待补充`、`SRC-?`、`Q-?` 已替换或明确保留为待确认项。
- Mermaid 代码块语法完整。
- `README.md` 中的产物清单、功能清单和阻塞问题数量与实际文件一致。

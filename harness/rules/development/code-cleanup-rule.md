# 代码清理 Rule

## 目标

在代码变更完成后，及时清理本次变更已替代、已废弃或已失效的旧代码，避免新旧实现并存、双轨逻辑长期残留和无效代码持续堆积。

## 优先级

- 本规则是代码变更任务的高优先级规则。
- 只要发生代码修改，就应同步评估是否存在需要一并清理的旧代码、废弃代码、失效参数、无用分支、无效映射或陈旧文档描述。

## 使用要求

- 当新实现已经明确替代旧实现时，应及时删除直接相关的旧代码，不以“先留着备用”作为默认做法。
- 不保留没有明确兼容依据的双轨逻辑、双入口、双字段映射或双套页面行为。
- 若必须暂时保留旧实现，必须有明确依据，例如兼容期、灰度期、外部依赖尚未切换完成；并在结果说明中明确保留原因、边界和后续清理条件。
- 清理范围应聚焦于当前变更直接涉及的代码与配套资产，不借机扩展为无边界重构。
- 代码切换完成后，应同步清理直接相关的无效导入、废弃注释、失效配置、陈旧常量、旧接口参数、旧网关描述、旧文档口径和无意义测试数据。
- 对用户或其他协作者已产生的有效改动，若不属于本次变更直接替代范围，不得以“清理旧代码”为名擅自删除或回退。

## 验收检查

- 是否仍残留本次需求已明确废弃的旧实现或旧分支。
- 是否仍存在没有实际调用价值的旧参数、旧字段映射或旧接口契约。
- 是否出现新旧逻辑并存但缺少明确兼容理由。
- 是否已同步清理本次变更直接影响到的文档、注释、配置和配套描述。

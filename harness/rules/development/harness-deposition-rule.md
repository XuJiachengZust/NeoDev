# Harness 沉淀 Rule

## 目标

把一次性问题处理过程中的稳定经验，持续沉淀为可复用的 harness 资产。

## 每次完成改动后的固定动作

每次修改完成后，都应判断本次产出中的经验、约束、边界、排查方式、提交规范或业务知识，是否值得沉淀到 harness。

## 适合沉淀的内容

- 多次出现的代码组织约束
- 容易误判的模块边界或配置边界
- 稳定可复用的排查步骤
- 当前仓库内特定模块的接口、验证、提交约束
- 共享术语定义和参考源优先级
- 单仓库长期稳定的协作规则

## 不适合沉淀的内容

- 仅服务单次需求的临时决定
- 缺少需求或代码依据的推测
- 会快速失效的环境状态
- 与现有规则重复但没有新增信息的描述

## 放置判断

- 当前仓库稳定开发规范：放到顶层 `harness/rules/development/`
- 环境、联调、部署口径：放到 `harness/context/`
- 常用示例或执行模板：放到 `harness/examples/`
- 总提示与维护约定：放到 `harness/system/`

## 仓库边界要求

- 顶层 `harness` 只沉淀当前仓库长期稳定、可复用的协作规则
- 若经验只对应一次性任务、一次性排障或临时环境状态，不要写入 `harness`
- 若一条规则同时涉及通用协作和具体实现，应先抽取稳定判断，再避免把一次性结论写成长期规则

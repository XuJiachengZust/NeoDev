# 用户心智如何驱动 NeoDev 产品规划

## 一、核心原则

这套材料现在按下面这条主链组织：

> **用户心智研究 → 战略定位 → P0 产品定义 → 执行任务包 → 实证验证**

也就是说，产品规划不再单独作为一堆功能与排期文档存在，而是明确以“用户应该如何重新理解研发协作”作为上游约束。

## 三、对老大的实际价值

这样整理后，老大不需要在“战略稿、PRD、周计划、任务包”之间自己拼逻辑。

现在的阅读方式变成：

1. **先判断心智方向是否成立**
2. **再判断这个方向压出来的 P0 是否够锋利**
3. **再判断第一批执行任务是否真的服务这个 P0**
4. **最后再看怎么验证，而不是先堆执行细节**

这能减少两个常见问题：
- 还没确认产品认知框架，就先掉进功能清单
- 还没确认 P0 骨架，就先掉进排期与派工
